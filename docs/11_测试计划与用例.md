# Atomlet（小原子）测试计划与用例

版本：v1.0　适用范围：48 小时交付窗口内的演示版本
关联文档：01 需求、02 架构、03 AppSpec 定义、05 生成链路、08 分享与权限、10 部署
交付形态：在线可访问链接 + 演示主路径现场跑通

---

## 1. 测试目标

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G1 | 演示主路径在冷启动环境下 100% 可跑通 | 演示前冒烟清单 12 条全绿 |
| G2 | 生成链路的失败有可读反馈，不出现白屏或永久卡住 | 超时/失败/非法输出三类异常均有终态 UI |
| G3 | 分享填报链路的权限边界不被绕过 | 无 token、过期、只读三类越权用例全部拦住 |
| G4 | 增量修改与版本回滚不破坏既有数据 | 修改前后、回滚前后记录数与内容一致 |
| G5 | 面试官常用环境（手机窄屏、Chrome）打开可用 | 375px 真机可完成一次填报 |

**非目标**：不追求覆盖率数字，不做性能压测，不做多用户长稳测试。理由见第 2 节。

---

## 2. 测试策略：分层抽测 + 演示路径全量覆盖

本项目不采用"全量测试"，采用两段叠加策略，原因有三点。

**第一，预算约束是硬的。** 开发预算 6-8 小时，如果按常规做全量单元测试加 E2E 回归，测试成本会超过开发成本本身。48 小时窗口里真正的稀缺资源是人的注意力，不是服务器。

**第二，交付物是"一次演示"，不是"一个持续运维的系统"。** 面试方评估的是"这个东西真的能用"，判定发生在演示的那 15 分钟里。因此所有和演示路径重叠的环节必须全量覆盖（哪怕用例很土，也要一条一条过），而演示路径之外的边角（例如 8MB 以上大文件、并发 50 人、跨时区日期）抽测即可。

**第三，风险驱动选择范围。** 我们按"发生概率 × 演示可见度"排序挑用例：生成链路失败概率最高、可见度最高，所以 P0 用例集中在这里；JSONB 深分页这类问题概率低且演示时不会被翻到，所以只保留 1 条 P2。

具体的分层边界：

| 层级 | 覆盖对象 | 执行方式 | 时间预算 |
|---|---|---|---|
| 单元 | AppSpec 的 zod schema 校验器；JSON Patch 作用域校验器（只允许 `/pages/*`、`/fields/*`，拒绝 `/appId`、`/shareToken`）；token 过期判断函数 | 自动化，vitest，5-8 个文件 | 30 分钟（含写） |
| 集成 | `/api/generate` 三阶段链路（模型打桩返回固定 AppSpec）；`/api/records` 增删改查 + app_id 隔离；`/api/share/[token]` 三种权限分支 | 自动化，接测试库 | 20 分钟（含写） |
| 端到端 | 演示主路径：新建 → 生成 → 填报 → 追加记录 → 对话改需求 → 回滚 | 手工为主；关键 3 条可加 Playwright，时间不够则跳过 | 60 分钟 |
| 探索性 | 现场自由试用，模拟面试官乱点 | 手工，15 分钟定时 | 15 分钟 |

自动化总量刻意控制在 10 个测试以内。凡是"自动化写起来比手工点一次更慢"的用例，一律标为手工。

## 3. 测试范围

**在范围内**

- 上传解析：xlsx / csv 的字段抽取、类型推断、脏字段清洗、空数据与超限处理
- 生成链路：Planner → Builder → Critic 三阶段、失败回灌重试、超时与中断、重复提交
- 六组件渲染：form / table / detail / stats / board / chart，含空态
- 记录读写：新增、编辑、删除、分页、类型校验、必填校验、超长与特殊字符
- 分享填报：token 生成、匿名填报、过期、只读、并发；对话修改：JSON Patch 应用、非法路径拒绝、旧数据保留
- 版本回滚与入口：版本列表、回滚后页面与数据一致性、刷新保持登录态、深链接直达、移动端窄屏

**不在范围内**

- Stripe 支付、SEO 元信息、自定义域名、代码导出、多人协同编辑（产品明确不做）
- 性能与容量：并发 50 以上、单应用 10 万条记录、生成 P95 延迟
- 国际化、无障碍合规、深度浏览器兼容（仅验收 Chrome + iOS Safari）；安全只做权限越权的功能级验证，不做注入与 XSS 深度利用
- 邮件、短信等外部通知通道

## 4. 测试环境与数据准备

### 4.1 环境

| 项 | 配置 |
|---|---|
| 运行环境 | 本地 `dev`（Node 20 / pnpm）+ 线上预览环境（部署平台的 Preview 地址）各一套 |
| 数据库 | Postgres 16（本地容器）；测试库与演示库物理分离，避免测试数据污染演示应用 |
| 模型 | 主账号 key + 备用账号 key 各一，配置文件里可一键切换 |
| 网络 | 常态网络；用 DevTools 的 Slow 3G 与 Offline 模拟弱网和断网 |
| 浏览器 | Chrome 最新版（桌面）；iPhone + Safari 真机 1 台；DevTools 设备模拟 375×812 辅助 |
| 数据核对 | 用 Drizzle Studio 或 `psql` 直接查 `app_records`，不只信前端展示 |

**每轮测试前必须重置数据库到干净状态**，否则分页和统计用例的数字不可复现。

## 8. 缺陷分级与处置

| 级别 | 定义 | 典型例子 | 处置约定 |
|---|---|---|---|
| P0 阻断 | 演示主路径无法完成，或数据安全越权 | 生成必失败；六组件有一个白屏；分享链接打不开；只读 token 能写入；跨 app 能读到别人数据 | 立即停下手上的新功能，当轮修完再继续；修完必须重跑最小必测集 8 条；未修复不得交付 |
| P1 严重 | 主路径可绕行，但演示时会被看到或数据会错 | 必填校验失效；超长需求被截断；断网后永久卡死；过期 token 未拦 | 当天修；若到交付前 1 小时仍未修，必须在演示脚本里绕开（不做该动作），并记入遗留清单 |
| P2 一般 | 边角场景错误，演示不涉及 | 大 CSV 解析慢；单点图表显示不佳；删字段后历史值显示异常 | 记入清单，按剩余时间修；不阻塞交付 |
| P3 轻微 | 观感/文案问题 | 长文本截断省略号位置；版本列表时间格式 | 攒批处理，可带入遗留清单 |

配套约定三条：**同一轮里 P0 优先于一切**，包括写文档、做截图、优化文案；**每个缺陷必须带复现步骤和一条实际观察到的现象**（截图或日志），不接受"感觉有问题"；**修复不等于通过**，任何 P0/P1 修复后必须回到对应用例重跑，并在缺陷记录里写上重跑结果与时间。
