## 一、这个 Demo 是什么（一页纸）

**一句话**：上传一张 Excel 表格，或说一句业务痛点，Atomlet 用一组智能体把它生成一套能用的内部系统——录入表单、记录列表、详情、统计看板——数据真实入库，能生成分享链接让别人填报，还能用一句话继续改。

**它解决谁的问题**：一线业务人员手里有一堆"用 Excel 很难受"的流程（门店巡检、报销登记、物资领用、客户回访）。他们不会写代码，也等不起 IT 排期。

**和 Atoms 的关系**：Atoms 让创业者做"能赚钱的产品"；Atomlet 让业务员把 Excel 变成系统。粒度更小、场景更窄，但"从想法到可用"这条链路是完整的。

**和常见 AI 生成工具的区别（这是技术主张，也是面试的考点）**：

| 做法 | 生成物 | 第二句话改需求会怎样 |
|---|---|---|
| 直出整页 HTML | 一段代码 | 整页重生，改 A 坏 B |
| **AppSpec 声明式（本方案）** | 一份受 JSON Schema 约束的"应用说明书" | 输出 JSON Patch，只改目标节点，版本 +1 可回滚 |

选择声明式，换来三件事：**可校验**（结构错误能在渲染前拦住）、**可增量**（改需求不重生成）、**可持久**（实体定义天然映射到数据模型）。

## 三、五条关键决策（会被追问，先记住）

1. **不直出 HTML，生成 AppSpec**。表达力换确定性。代价：组件只有 6 个，长不成任意网站。
2. **数据不做运行时 DDL**。逻辑上"一应用一套模型"，物理上用统一 `app_records` 表 + JSONB + `app_id` 隔离 + 字段级校验。理由：避免注入与迁移失控，多租户成本低。演进路径见 06 的 ADR-01。
3. **增量修改只输出 JSON Patch，不重生成**。路径不存在就丢弃该条并提示，绝不整页重生。
4. **生成失败三级兜底**：schema 重试 → 局部修复 → 回退最接近的模板并明确告知用户。不假装成功。
5. **分享链接必须能填、数据必须真入库**。这是"可用"和"PoC"的分界线，任何时间压力下都不砍。

## 四、开始开发的第一个小时

```
0:00-0:10  按 09 的 Dockerfile / docker-compose 起本地 Postgres，跑通 drizzle push
0:10-0:20  建 apps / app_versions / app_records / share_links / gen_runs 五张表（08 的 DDL）
0:20-0:35  上线通道先打通：首页能访问，部署成功（哪怕只有一个空壳页）
0:35-1:00  接入一个 LLM provider，跑通"输入需求 → 输出 AppSpec JSON"的最小闭环
```

先把"能上线"和"能生成"两件事各自打通，再往上叠组件——这样任何一个时间点中断，你手上都有一个能演示的东西。

## 五、三个需要你拍板的决策（我的建议已给出）

| # | 决策 | 我的建议 | 理由 |
|---|---|---|---|
| D1 | 分享链接要不要支持"只读模式" | **升为 P0**，砍掉 P1 的"新手动线引导" | 演示时一句"转发给老板，他能看但不能改"就把多人协作的真实感讲透了，成本约 0.15h |
| D2 | 生成的应用配色布局交给模型还是固定 | **固定 4 套预设主题**，模型只能选一个枚举值 | 交给模型自由发挥是演示翻车的第一大原因（观感不可控）；固定主题约 30 行代码 |
| D3 | 部署在哪 | **阿里云 ECS + Docker + Postgres**（有就用）；没有则 Vercel + Neon | 见 09：Vercel 的只读文件系统是这类 Demo 最常见的踩坑点 |

另有一件必须提前做的事，已排进 P0：**准备 3 个已生成好的应用作为降级演示入口**（见 12 的降级剧本）。生成链路再稳，也不要把整场演示压在"现场临时生成成功"上。

## 七、口径裁决记录

四份文档并行产出后，有两处口径冲突已裁决，以本节为准（正文已同步修正）：

| 冲突点 | 出现位置 | 裁决 | 依据 |
|---|---|---|---|
| 字段类型：8 种还是 9 种 <br>（`currency`/`boolean` vs `url`/`bool`/`user`） | 02 写 8 种，07/08/14 写 9 种 | **以 9 种为准**：`text / longtext / number / date / enum / bool / url / ref / user` | 类型必须与渲染器控件一对一，否则 Builder 会产出无法渲染的字段。金额与百分比是 `number` 的展示格式，不单列为类型 |
| 图表类型取值 | 07 写 `bar/line/donut` | 统一 `bar / line / donut` | 渲染器不接受越界值，越界即降级为 table 并提示 |
| 聚合表达式归属 | 07 写在页面级 `aggregations`，08 按 `stats.cards[].fn` 存 | **按 08 落库**：`stats.cards[].fn` 与 `chart.metric.fn` | 聚合属于具体指标卡/图表，页面级无法区分多个不同口径的指标 |
| `chart` / `board` 组件的优先级 | 07 列为六组件之一，13 标 P1 | **P1（时间允许）**，P0 只做 form / table / detail / stats | 4 小时节点若未完成，按 10 的砍功能顺序直接放弃，不影响主流程完整性 |

**还剩一个自由度没有锁死**：分享链接是否区分只读/可写，见 D1；这条不影响数据结构（`share_links.scope` 字段已预留），只在界面上决定是否暴露切换。
| 21 | [交互式页面支持](21_交互式页面支持.md) | 真实交互 + 数据持久化怎么做 | 开发 / 面试官 |
